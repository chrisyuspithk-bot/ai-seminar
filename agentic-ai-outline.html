《從 LLM 到 Agentic AI：原理、框架與實戰》課程大綱

先看懂 AI 如何從「會說話」走到「會做事」，再看多代理協作的兩個真實案例——中國 Kimi 的 Agent Swarm 與日本 Sakana 的 Fugu 編排器，接著盤點業界的框架與工具，最後在 Mac 上親手用 OpenWorkers 生成 PPT、用 OpenHands Cloud 一句 Prompt 做出一個 App。

受眾 大學生 · 職場初學者 形式 講述 ＋ OpenWorkers／OpenHands 現場操作 時數 120 分鐘 簡報 agentic-ai-deck.html · 34 頁

下課後，學員帶走這六件事

01

用自己的話說出 LLM、RAG、AI Agent、Agentic AI 四層躍遷的差別。

03

05

在 Mac 上實際操作 OpenWorkers，從素材到交付完成一份 PPT 檔案。

06

在 OpenHands Cloud 用一句 Prompt 完成一個可運行的待辦事項 App。

Part 2 · 15 分鐘

Agentic AI 與 LLM 的根本差異

投影片 04–08
04

三、從會說話到會做事

1 頁
  • 04
    從「會說話」到「會做事」 — 生成式 AI 產出的是「內容」；Agentic AI 是會在世界中採取行動的 AI，行動可以是物理的（機器人操作），也可以是數位的（幫你訂機票）。
05–06

四、四層智能躍遷

2 頁
  • 05
    四層智能躍遷：像四級台階 — LAYER 1 LLM（會不會說）、LAYER 2 RAG（有沒有依據）、LAYER 3 AI Agent（能不能做事）、LAYER 4 Agentic AI（能不能協同）。
  • 06
    一句話記住 — LLM 是智能的語言引擎、RAG 是知識底座、AI Agent 是任務執行單元、Agentic AI 是組織協同系統；每一層都是疊加，無法跳過。
07–08

五、五大架構與關鍵比喻

2 頁
  • 07
    Agentic AI 的五大核心技術架構
    • ① LLM 當大腦、② 工具整合、③ 記憶機制、④ 規劃與反思、⑤ 多代理協作。
    • 前四項讓單一 Agent 變強，第五項「多代理協作」是這一輪最關鍵的發展，也是下一個 PART 的主角。
  • 08
    聰明的秘書 vs 全權代理人 — 傳統生成式 AI 像秘書（你交代什麼做什麼）；Agentic AI 像全權代理人（一句「幫我計劃下個月去日本，預算兩萬元」，自己查機票、酒店、天氣與行程）。提醒：能力越強，信任與監督機制越重要（人在迴路）。

Part 3 · 20 分鐘

Agent Swarm 多代理協作

投影片 09–16
09

六、為什麼需要多代理

1 頁
  • 09
    如果一個 Agent 不夠強，為什麼不訓練一個更強的？ — 複雜任務需要的專業知識遠超單一模型邊界；與其訓練「全能模型」，不如讓多個專責模型協同。核心思想：智能不在節點，而在關係。
10–12

七、中國案例：Kimi Agent Swarm

3 頁
  • 10
    月之暗面與 Kimi K3 — 2.8 兆參數、200 萬 token 上下文、896 路由專家（每次激活 16 個）；真正的重點是 Agent Swarm 產品支援最多 100 個並發子智能體。
  • 11
    代理群怎麼運作？ — 動態生成最多 100 個子代理、最多 1,500 次工具呼叫、執行時間最多縮短 4.5 倍；整個代理群由模型自動建立與調度，無需事先定義角色。
  • 12
    不只是「向上擴展」，還要「向外擴展」 — 月之暗面的方向：更大的模型 ＋ 更多的 Agent；引用明斯基《心智社會》(1986)——智能存在於組件的組織方式之中。
13–15

八、日本案例：Sakana AI

3 頁
  • 13
    Sakana Fugu：AI 的「總指揮」 — 2023 年成立的日本獨角獸，由 Transformer 論文第五作者 Llion Jones 共同創辦；Fugu 是 2026 年 6 月的編排器模型，自己不回答問題，而是調用世界上各種模型。
  • 14
    Fugu 的四個基礎機制
    • ① 識別問題類型、② 選擇 worker 模型、③ 拆解任務、④ 校驗與綜合。
    • 核心精神：不訓練更強的基座去解題，而是判斷「這道題該交給誰、怎麼拆、如何驗證」。
  • 15
    性能表現與「AI 主權」 — Terminal Bench 峰值集中在 GPT-5.5、GPQA Diamond 圍繞 Gemini 展開；戰略上從 Anthropic 出口管制吸取教訓，底層模型池完全可替換。編排能力本身正成為一種獨立的競爭力。
16

九、兩個案例對比

1 頁
  • 16
    Kimi Agent Swarm vs Sakana Fugu — 對比核心策略、Agent 數量、角色定義、戰略定位與獨特價值：Kimi 靠 100 個並發子代理縮短 4.5 倍時間；Fugu 靠編排器打破單一供應商依賴。

從框架到工具

投影片 17–21
17–18

十、框架層：開發者如何構建 Agent

2 頁
  • 17
    Google ADK（Agent Development Kit） — 2025 年 4 月 Cloud NEXT 發布的開源框架。
    • 四大特色：Multi-Agent by Design、豐富模型生態（LiteLLM 整合）、豐富工具生態（含 MCP）、內建評估。
    • Google 自家 Agentspace 與 Customer Engagement Suite 即採用此框架。
  • 18
    LangGraph：把工作流畫成一張圖 — LangChain 團隊開發，用於有狀態的、多參與者的 LLM 應用；四個概念：StateGraph、Node、Edge、Persistence（支援記憶、中斷恢復、人工參與）。實際用戶：LinkedIn、Uber、Klarna、GitLab。
19

十一、框架選擇的思考

1 頁
  • 19
    兩種設計哲學
    • Google ADK：企業整合派，強調 GCP 整合、企業級部署與完整評估工具鏈。
    • LangGraph：精細控制派，強調流程控制、狀態管理與中斷恢復能力。
    • 怎麼選取決於技術棧、部署環境與團隊熟悉度，沒有標準答案。
20–21

十二、工具層與層次關係

2 頁
  • 20
    不用自己寫框架，直接拿來用 — OpenHands（原名 OpenDevin，GitHub Star 超過 7.4 萬；Cloud／CLI／Local GUI／Software Agent SDK）；OpenWorkers（吳恩達團隊開源；交付成品、本地優先＋任意模型、每個重要動作都有審批）。
  • 21
    四個層次，由上而下 — Agentic AI 應用層 → 框架層 → Agent 運行時層 → 模型層；界線正在模糊（OpenHands 同時提供 SDK 與 Cloud GUI）。

Mac 實戰 Demo：OpenWorkers

投影片 23–26
23–24

十三、環境準備與下達指令

2 頁
  • 23
    環境準備
    • macOS 13+、至少 8GB RAM（建議 16GB）、Node.js v20+、一組 LLM API Key。
    • 從 GitHub 下載 macOS 安裝檔、拖入「應用程式」，首次啟動設定 API Key（教學建議 DeepSeek 或 Kimi，成本較低）。
  • 24
    準備素材，然後下達指令 — 桌面 ProductLaunch 資料夾含 product_features.md、market_data.csv、competitor_analysis.md；在對話框輸入一段要求產出 6 部分、.pptx 格式、檔名 ProductLaunch_Presentation 的指令。
25–26

十四、觀察工作流程與設計哲學

2 頁
  • 25
    Agent 自己拆解、自己交付 — 五步驟：規劃階段 → 讀取檔案 → 生成內容 → 創建簡報 → 檢查與交付。
    • 它給你的是成品：可直接打開、可分享的簡報檔案，而不是一段文字。
  • 26
    它提議，你拍板 — 內容不理想就直接說，OpenWorkers 會記住上下文修改對應頁面。三大設計哲學：
    • 本地優先：檔案處理都在你的 Mac 完成。
    • 審批門控：要執行重要操作時會停下來等你確認。
    • 連接器生態：可連接 HubSpot、GitHub、Slack 等 25 個以上服務。

操作提示本段是第一個動手環節，學員可同步操作；網路不穩時可改用預先準備的成品檔。

Part 6 · 20 分鐘 · 動手做

OpenHands Cloud 教學

投影片 27–31
27–28

十五、架構解析與快速上手

2 頁
  • 27
    OpenHands 的架構解析
    • 核心（LLM · Agent）、環境（Runtime · Sandbox）、服務（Server）、骨幹（EventStream）。
    • 它給 LLM 配備完整開發環境，是一個能驗證程式碼是否正確執行的閉環回饋系統。
  • 28
    三個步驟開始
    • 註冊帳號：app.all-hands.dev，用 GitHub 或 GitLab 登入，新用戶有免費額度。
    • 設定模型：Settings → LLM；OpenHands 模型無關，支援 OpenAI／Anthropic／Google／LiteLLM。
    • 開始新任務：Launch from Scratch。初學者建議先選 Claude 或 GPT 系列。
29–31

十六、一句 Prompt 做出一個 App

3 頁
  • 29
    我們只給它這一段話 — Prompt 要求用 Python Flask 建待辦事項 Web App：新增／編輯／刪除、標記完成、SQLite、原生 HTML+CSS、README、測試，並啟動伺服器驗證。
  • 30
    從規劃到交付，六個階段 — 規劃 → 環境準備 → 程式碼編寫 → 測試與除錯（自我迭代）→ 啟動與驗證 → 交付。
  • 31
    這不只是生成程式碼，而是完成一整個開發任務 — 四大設計原則：Sandbox 隔離、EventStream 驅動、模型無關、原生沙盒化。

操作提示本段是第二個動手環節，可讓學員直接複製 Prompt 現場跑一次。

Part 7 · 總結與 Q&A · 5 分鐘

從原理、案例，到實戰

投影片 32–34
32

十七、四個層次的總結

1 頁
  • 32
    我們從四個層次理解了這個轉變
    • 概念層：四個階梯（LLM／RAG／AI Agent／Agentic AI）。
    • 案例層：Kimi 用 100 個並發子代理提升 4.5 倍效率；Sakana Fugu 用編排器調度多個專家模型。
    • 框架層：Google ADK 與 LangGraph，分別代表企業整合與精細控制。
    • 工具層：OpenWorkers 與 OpenHands，讓每個人都能實際使用 Agentic AI 的能力。
    一句話：Agentic AI 代表 AI 從「輔助工具」進化為「生產力主體」的關鍵轉折。
33–34

十八、三個 takeaway 與結語

2 頁
  • 33
    帶走三句話
    • ① 價值不在模型，而在系統。
    • ② 編排能力是獨立競爭力。
    • ③ 安全與信任是前提。
    下一步建議：下載 OpenWorkers 跑真實任務、申請 OpenHands Cloud 免費額度、用一句 Prompt 做出小工具。
  • 34
    結語 — 未來 AI 的競爭，未必只屬於擁有最強單體模型的公司，也可能屬於最擅長設計關係的公司——模型內部的關係、智能體之間的關係，以及 AI 系統與人類之間的關係。
