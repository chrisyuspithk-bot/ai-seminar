從「LLM 是機率機器」的原理出發，一路走過開源模型、量化與 Hugging Face，親手在 LM Studio 跑起本地模型，再用 COSTAR、RAG、MCP 把它變成會做事的助手，最後收束在 Gemini 生態系與「什麼情境用什麼工具」的判斷力。

課程目標

下課後，學員帶走這六件事

01

用自己的話解釋 LLM 的運作原理：它做的是機率預測，不是查資料庫。

02

分辨開源與閉源模型，以及文本／多模態／Embedding／Omni 四種模型類型的差異。

03

理解量化（Q4_K_M）與 GGUF，並在 Hugging Face 找到可直接使用的本地模型。

04

獨立完成 LM Studio 的安裝、下載模型、載入對話與進階設定。

05

用 COSTAR 框架寫出有效 prompt，並理解 Token、上下文窗口、RAG 與幻覺。

06

理解 MCP 與工具調用，並能判斷什麼任務該用本地、什麼該上雲端 Gemini。

Part 1 · 25 分鐘

LLM 基礎概念

投影片 01–04
01–02

一、開場與 LLM 的本質

2 頁
  • 01
    封面 — 150 分鐘實戰課 · 八個 PART；標題《從 LLM 基礎概念到 LM Studio 與 Gemini》，封面即列出八個 PART 與各自分鐘數。
  • 02
    ChatGPT 到底在「做」什麼？ — 不是查資料，而是做下一個詞的機率預測：接收輸入（切成 token）→ 計算機率 → 逐個生成。金句：LLM 是機率機器，不是知識庫。

教學提示用「英文約 1 token ≈ 0.75 個單字、中文約 1 字 ≈ 1–2 token」讓學員對 token 有量感。

03–04

二、架構與參數規模

2 頁
  • 03
    Transformer 與自注意力機制 — Self-Attention 讓模型生成每個詞時回頭看整個序列，判斷哪些最相關；以「小明把蘋果給了小華，因為他很餓」示範代名詞判斷。
  • 04
    參數規模：4B、7B、70B — B 代表 Billion（十億）。4B 輕量（8GB RAM 有機會跑）、7B 甜蜜點、70B 重裝旗艦（需高階 GPU）。實務結論：本地跑 7B–13B 已非常可行。

Part 2 · 15 分鐘

開源 vs 閉源、模型類型解析

投影片 05–06
05–06

三、開源閉源與四種模型類型

2 頁
  • 05
    開源 vs 閉源模型
    • 閉源：只能透過 API 使用、看不見權重（GPT-4o、Claude）；性能最強、開箱即用，但資料上傳、付費、無法自訂。
    • 開源：可下載權重自己跑（Llama 4、DeepSeek V3、Qwen 3）；資料不出本地、免費、可微調，但硬體門檻與設定複雜度高。
    • 提醒：「開源」與「開放權重」技術上不同，業界講開源通常指後者。
  • 06
    文本、多模態、Embedding、Omni — 用「輸入 → 輸出」一次分清：文本（文字→文字）、多模態（文字＋圖片→文字）、Embedding（文字→向量，把語意變成座標）、Omni（任意模態→任意模態，如 Jina v5-omni）。

Part 3 · 15 分鐘

量化與 Hugging Face

投影片 07–08
07–08

四、量化與模型檔案格式

2 頁
  • 07
    什麼是量化？ — 原始模型用 FP16 儲存，70 億參數光參數就要約 14 GB；量化把數字從 16 位元壓到 8／4 位元甚至更低，比喻為高解析照片轉存 JPEG。
    • Q8：品質接近原始，檔案仍偏大。
    • Q4_K_M：最推薦的平衡點，比 FP16 少用約 40% VRAM，品質損失不到 1%。
    • Q2：極致壓縮，品質損失明顯。
  • 08
    Hugging Face 與 GGUF — HF 是 AI 界的 GitHub；GGUF 是 llama.cpp 生態系的本地推理格式。操作：搜尋「模型名稱 + GGUF」→ 在 Files 區塊找 .gguf 檔 → 挑量化版本下載。

Part 4 · 30 分鐘 · 動手做

LM Studio 安裝與設定實操

投影片 09–14
09–10

五、認識 LM Studio 與安裝

2 頁
  • 09
    LM Studio 是什麼？ — 免費桌面應用程式，用圖形介面在本地跑 LLM、不必寫程式。四大優勢：圖形化操作、內建模型搜尋、完全離線、OpenAI 相容 API。
  • 10
    下載與安裝
    • STEP 1 前往官網 lmstudio.ai 點 Download。
    • STEP 2 依作業系統選版本（Windows／macOS／Linux）並安裝。
    • STEP 3 首次啟動後從 Settings → General → Language 選「繁體中文」。
    • 注意：非英文語言包仍為測試版，部分介面可能顯示英文，不影響功能。
11–12

六、搜尋、下載、載入與對話

2 頁
  • 11
    搜尋與下載模型（現場操作） — 左側邊欄四個按鈕：Chat／Developer／My Models／Discover。
    • Discover → 搜尋 Qwen2.5-7B-Instruct-GGUF → 選可靠發布者（如 bartowski 或 Qwen 官方）→ 選 Q4_K_M → Download（約 4–5 GB）。
  • 12
    載入模型與基礎對話 — 回 Chat → 選剛下載的模型並載入 → 試輸入「用繁體中文自我介紹一下。」
13–14

七、進階設定與 Local API

2 頁
  • 13
    GPU、上下文長度與 Temperature
    • GPU Offload：控制多少層跑在 GPU，預設 100%；低於 50% 速度大幅下降。
    • Context Length：預設 4096 可調高；上下文翻倍，VRAM 用量也翻倍。
    • Temperature：低溫 0.1–0.3 適合事實問答；高溫 0.7–1.0 適合創意寫作。
    • n_parallel：LM Studio 0.4.0 新功能，同時處理多個推理請求，預設 4 個並行槽位。
  • 14
    內建 OpenAI 相容 API — Developer 頁點 Start Server，運行於 http://localhost:1234；任何支援 OpenAI API 的程式庫都能連接（附 Python 範例）。意義：把 LM Studio 當成免費的本地 API。

操作提示本段是第一個動手環節，學員可同步操作；網路不穩時可改用已下載的 GGUF 檔。

Part 5 · 20 分鐘

Prompt 工程與核心概念

投影片 15–20
15–16

八、Prompt 的重要性與 COSTAR 框架

2 頁
  • 15
    Prompt 是你跟模型溝通的唯一介面 — 同樣的模型、不同的 prompt，輸出品質差距很大。核心原則：模型不知道你腦子裡在想什麼，要把「理所當然」的背景資訊全寫進 prompt。
  • 16
    COSTAR：六個要素 — C 上下文（Context）、O 目標（Objective）、S 風格（Style）、T 語氣（Tone）、A 受眾（Audience）、R 回應格式（Response）。實戰建議：不必每次寫滿六項，但 C 與 O 絕對必要。
17–18

九、Token／上下文窗口與 RAG

2 頁
  • 17
    Token 與上下文窗口 — Token 是模型處理文字的最小單位；上下文窗口含 prompt + 回應 + 所有歷史對話。超出窗口時最舊內容會被「擠出去」，這就是長對話中模型「忘記」前文的原因。
  • 18
    RAG 與 Embedding — 五步：切塊 → 用 Embedding 轉向量 → 存向量資料庫 → 提問時找相似文檔塊 → 文檔塊＋問題一起餵給 LLM。Embedding 讓「語意相似度」變成可計算的向量距離。
19–20

十、幻覺與工具調用

2 頁
  • 19
    幻覺：模型為什麼會「一本正經地胡說」
    • 三大原因：訓練目標的錯位、訓練資料的污染、解碼策略的隨機性。
    • 四招降低：明確要求「不確定就說不知道」、使用 RAG、降低 Temperature、交叉驗證回答。
  • 20
    讓模型從「說話」變成「做事」 — 工具調用（Tool Calling）讓模型在需要時呼叫外部函數（範例：查天氣 API）。下一站：MCP 解決「每個工具都要寫適配程式碼」的問題。
陸

Part 6 · 15 分鐘 · 實戰展示

MCP 與工具調用

投影片 21–24
21–22

十一、MCP 是什麼、怎麼設定

2 頁
  • 21
    MCP 是什麼？ — Anthropic 於 2024 年提出的 Model Context Protocol，比喻為 AI 的 USB-C 接口。
    • 三個角色：Host（你的 LLM 應用）、Client（MCP SDK，管理連接）、Server（提供工具的服務，stdio 或 HTTP）。
    • 與 Function Calling 互補而非替代：前者解決「單模型怎麼調用自己的 API」，MCP 解決「如何標準化工具接口，讓多個 Agent 共享多個工具」。
  • 22
    在 LM Studio 中設定 MCP
    • 方法一：切換右側 Program 分頁 → Install > Edit mcp.json。
    • 方法二：直接編輯 ~/.lmstudio/mcp.json（macOS）或 %USERPROFILE%\.lmstudio\mcp.json（Windows）。
    • 附基本 mcp.json 範例；儲存後重新啟動或點 Reload MCP servers。
23–24

十二、實戰 Demo 與 Web Search

2 頁
  • 23
    實戰：讓模型使用工具 — 載入支援工具調用的模型（如 Qwen 系列）＋ filesystem MCP server，問「幫我讀取桌面上的 test.txt」。
    • 四步流程：判斷意圖 → 生成工具調用請求 → MCP Client 執行工具並回傳 → 模型生成最終回答。
  • 24
    Web Search MCP — 設定 web search server 後可問即時資訊（如「今天台北的天氣如何？」）。這解決 LLM 的根本限制：訓練資料有截止日期。

Part 7 · 10 分鐘

本地模型的極限與雲端的必要性

投影片 25–26
25–26

十三、三個硬限制與混合策略

2 頁
  • 25
    本地模型的三個硬限制
    • ① 上下文窗口的物理天花板：1K 擴到 65K，抽取任務效能下降 13%；KV Cache 隨上下文線性成長，21GB 模型實佔可能暴增到 25–30GB，VRAM 溢出即崩潰。
    • ② 運算能力的本質差距：RTX 4090 的 24GB vs 雲端 H100 80GB 與 TPU 叢集；本地推論落後 1.4–7.4 倍。
    • ③ 模型「智商」的壓縮代價：本地模型幾乎都量化過，frontier 模型參數量是數十倍且未壓縮。
    一句話：本地是「夠用」，雲端是「好用」。
  • 26
    雲端的必要性與混合策略
    • 本地守備範圍：隱私／機密資料、離線工作、預算有限、實驗性專案。
    • 雲端守備範圍：複雜推理、長文件分析、需最新知識、生產環境關鍵工作。
    • 雲端優勢（100 萬 token、模型永遠最新、按用量付費）與代價（資料離開裝置、網路延遲、長期成本累積）；最務實的是混合架構。
捌

Part 8 · 20 分鐘 · 動手做

Gemini 生態系增強教程

投影片 27–33
27–29

十四、Gemini 是什麼、方案與 Gems

3 頁
  • 27
    Gemini 是什麼？不只是聊天機器人 — 它是一個生態系：模型家族含快捷、思考型與最強的 Pro 模型；並深度嵌入 Gmail、Docs、Sheets、Slides、Drive、Meet、Calendar。AI 就在你的工作流裡面。
  • 28
    Gemini 方案比較與選擇建議
    • 免費版 NT$0／15GB：日常查詢、輕度使用。
    • Google AI Plus NT$260／月·200GB：想試付費功能、預算有限。
    • Google AI Pro NT$650／月·2TB：學生、研究員、深度使用者。
    • Google AI Ultra NT$8,150／月·30TB：企業級應用、極致效能需求。
    • 付費版核心差異：上下文從免費版 32,000 token 躍升到 100 萬 token；思考型模型每日額度 300–1,500 個提示詞。
  • 29
    Gems：你的專屬 AI 專家 — 可建立預先設定指令與知識庫的 Gemini 分身。步驟：gemini.google.com → Gems → 新增 → 命名 → 寫指令 →（可選）上傳文件 → 儲存。指令範例：財報分析助手。
30–31

十五、Gems × Drive 與 Workspace 整合

2 頁
  • 30
    Gems × Google Drive：零程式碼的 RAG — 步驟：drive.google.com → 右上 Ask Gemini → 側邊欄選 Gems → 選你的 Gem → 直接提問，它會從 Drive 檔案檢索回答。
    • 應用場景：合約審閱、專案週報、論文助手。本質是個人化的 RAG 系統，且零程式碼。
  • 31
    Gemini 在 Workspace 中的深度整合
    • Google Docs：「Help me create」從相關 Drive 文件抓內容產出初稿；「Match writing style」統一多人協作文風。
    • Google Sheets：一句話描述要管理的專案，自動建立多工作表試算表。
    • Google Drive：跨檔案問答（例：上月與客戶 A 的往來郵件是否提到預算調整）。
32–33

十六、Gemini Live 與決策框架

2 頁
  • 32
    Gemini Live 與語音互動 — 即時語音對話，可用語音指令操作 Gmail（搜尋、摘要、加星標、歸檔、刪除）；「每日簡報」用語音總結重要郵件、行事曆與待辦。目前主要提供給 Google AI Pro 與 Ultra。
  • 33
    什麼時候用本地，什麼時候用 Gemini
    • 選本地（LM Studio）：敏感／機密資料、離線工作、預算有限、簡單生成與摘要翻譯。
    • 選雲端（Gemini）：超長文件（100 萬 token 等級）、需與 Gmail／Drive／Docs 深度整合、需最新模型能力、複雜推理與多步驟任務。
    • 混合策略：日常隱私任務給 LM Studio，需要強大推理與生態系整合的任務給 Gemini。

操作提示本段是第二個動手環節，可讓學員現場建立第一個 Gem 並用 Drive 檔案測試。

投影片 34–35
34

十七、八個帶得走的結論

1 頁
  • 34
    從原理、實戰，到生態系
    • ① LLM 是機率預測機器，是所有行為的基礎。
    • ② 開源模型讓你在本地跑，LM Studio 是最低門檻。
    • ③ 量化是本地運行的關鍵，Q4_K_M 是最佳平衡點。
    • ④ COSTAR 框架讓 prompt 更有效。
    • ⑤ MCP 讓模型能使用工具，從說話升級到做事。
    • ⑥ 本地模型有硬限制：上下文、運算、壓縮代價。
    • ⑦ 雲端 AI 是必要的互補，Gemini 展現工作流整合。
    • ⑧ Gems + Drive 是零程式碼 RAG，今天就能用。
    下一步五件事：跑一個 7B 模型、用 COSTAR 寫 prompt、創建自己的 Gem、在 Drive 用 Gem 分析文件、觀察工作流決定本地或雲端。

十八、結語

    結語 — 今天學到的不是「哪個工具比較好」，而是「什麼情境用什麼工具」。這種判斷力，比任何單一技術都更有價值。
