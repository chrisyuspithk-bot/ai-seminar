封面：從 LLM 基礎概念到 LM Studio 與 Gemini

02

ChatGPT 到底在「做」什麼？

好，我哋由一頁可能推翻你過往認知嘅投影片開始。你平時用 ChatGPT，你問佢「香港邊年回歸」，佢答「一九九七年」。你腦裏面好自然會覺得：佢去咗某個資料庫，搵到一九九七年呢個答案，然後抄返出嚟。唔係。佢冇一個資料庫畀佢查。

佢做嘅事，叫做「下一個詞嘅機率預測」。即係話，佢睇完你嗰句問題之後，心裏面計一次：如果我要跟住呢句嘢寫落去，下一個字最有可能係乜嘢？佢計完，揀一個，再加落去，然後再計下一個，一個字一個字咁砌出嚟。所以佢每次答你嘅時候，其實係喺度「續寫」，唔係喺度「查證」。

流程大概係三步。第一步，接收輸入：你打嘅字會先被切成一粒粒嘅 token，即係詞元。第二步，計算機率：模型睇住呢串 token，計出「下一個 token」嘅機率分佈。第三步，逐個生成：揀一個出嚟，加落去，再重新計下一次。呢三步會重複到你嘅答案寫完為止。

所以你要記住今日嘅第一句話：LLM 係一部機率機器，唔係一個知識庫。 呢句話會影響你之後所有判斷。因為如果佢係知識庫，咁佢答嘅嘢應該係準確嘅；但佢係機率機器，佢答嘅嘢係「最似樣」嘅，唔一定係「最準確」嘅。你之後見到佢一本正經咁講錯嘢，就唔會覺得奇怪。

順便講兩個實用數字。英文大概一個 token 等於零點七五個單字；中文就唔同，大概一個中文字等於一到兩個 token。呢個數字點解重要？因為你之後無論係本地模型定雲端模型，收費同埋限制都係用 token 計嘅，唔係用字數計。

補充有學員會問「咁佢點解會有知識」。答案係：佢嘅知識唔係儲存喺一個表度，而係壓縮咗喺幾十億個參數裏面。你可以想像成，佢讀過成個互聯網之後，將所有文字嘅統計規律「醃」咗入自己嘅數學結構裏面。所以佢講得出大概，但細節位好容易走樣。

學員可能問「咁即係佢完全唔識答問題？」唔係。佢識答，而且答得好過好多人；但佢係用「統計上最似樣」嘅方式答，唔係用「查證」嘅方式答。呢個分別，就係我哋後面要學 RAG 同查證嘅原因。

03

Transformer 與自注意力機制

上一頁講咗佢係逐個字續寫。咁問題嚟喇：佢點知下一個字應該係乜？呢一頁就係答案，亦係整個現代 AI 最核心嘅一個機制，叫 Self-Attention，自注意力。

我用一句中文例子講，你就明。呢句係：「小明把蘋果給了小華，因為他很餓。」你望住最後嗰個「他」，你腦裏面即刻知係小明，唔係小華。你點知？因為你同時間睇咗成句，再判斷「他」同邊個名最相關。自注意力做嘅，就係一模一樣嘅事。

當模型要生成每一個詞嘅時候，佢會「回頭望」一次序列裏面所有詞，然後為每個詞計一個相關分數。分數高嘅，影響就大；分數低嘅，影響就細。啱先嗰句，「很餓」呢個資訊會令模型加重「小明」嘅權重，所以佢判斷「他」係小明。

呢個機制有三個觀點值得你帶走。第一，注意力嘅本質係「相關分數」——佢唔係理解語意，佢係計邊個詞同邊個詞比較相關。第二，佢係一個突破，因為佢可以平行處理：以前嘅模型要一個字一個字順序睇，行到第十個字嘅時候，第一個字嘅記憶已經淡咗；自注意力可以一次過睇晒成串，所以佢可以同時訓練、可以處理好長嘅上下文。第三，就係因為有咗呢個突破，先至有可能出現今日嘅 LLM。

一句話總結：自注意力令模型生成每個詞嘅時候，都可以重新判斷「邊啲資訊最相關」。 唔需要死記，你只需要記住「佢會回頭望」就夠。

補充如果你想把呢個概念講得更生活化，可以話：佢好似一個開會嘅人，唔係只聽啱先嗰個人講乜，而係每一句話都重新掃一次全場，睇下而家邊個人講嘅嘢最關事。

04

參數規模：4B、7B、70B 的意義

跟住落嚟呢一頁，係你之後揀模型嘅實戰基礎。你上網見到啲模型名，通常有一組數字：Qwen 7B、Llama 70B、Gemma 4B。呢個 B 係 Billion，即係十億。7B 就係七十億個參數。

你可以將參數想像成模型嘅「腦容量」。參數越多，佢可以記住嘅規律越複雜，但同時佢需要嘅記憶體同算力就越大。呢個係一個非常現實嘅取捨，冇免費午餐。

我用三個級別同你分。第一個係 4B 級別，輕量級。呢個級別嘅模型，如果你部電腦有 8GB RAM，係有機會跑得起嘅，速度都接受到。但佢嘅推理能力比較淺，適合做簡單嘅改寫、翻譯、分類。第二個係 7B 級別，呢個係甜蜜點，亦係本地部署嘅主流。一般 16GB RAM 嘅機跑得順，質素同速度平衡得幾好，我今日示範會用嘅就係呢個級別。第三個係 70B 級別，重裝旗艦，需要高階 GPU，一般家用電腦唔使諗。

實務結論：如果你今日係第一次玩本地模型，目標就係 7B 到 13B 呢個範圍。 唔好一開始就去追 70B，因為你嘅硬件追唔上，載入唔到，你只會覺得「本地模型唔掂」而放棄。揀模型嘅第一步唔係揀最強，係揀跑得起。

教學提示呢度可以即場問一句：「有邊位部電腦係 8GB RAM 以下？」舉手嘅學員，之後 Part 4 你特別留意佢，因為佢要揀 3B 或以下嘅模型，唔係佢嘅錯，係硬件限制。 ---

開源 vs 閉源、模型類型解析（15 分鐘 · 05–06）

05

開源 vs 閉源模型

好，我哋轉去另一個維度：模型係邊個畀你用、用咩方式畀你用。呢個分野直接決定你嘅資料會去邊，所以唔係純技術問題，而係一個責任問題。

先講閉源模型。閉源即係你只可以透過 API 用佢，你永遠見唔到佢嘅權重。GPT-4o、Claude 就係呢類。優點好明顯：性能最強，開箱即用，你唔使理硬件，寫幾行程式就 call 到。缺點亦好明顯：你嘅資料要上傳去佢嘅伺服器；你要畀錢，用得多就貴；你唔可以改佢，唔可以微調佢去識你公司嘅術語。

再講開源模型。開源即係你可以下載佢嘅權重，喺自己部電腦跑。Llama 4、DeepSeek V3、Qwen 3 呢啲都係。優點係：資料完全唔出你部機，免費，你可以自己微調。缺點係：硬件有門檻，設定比較複雜，而且質素通常差少少。

呢度我要補一個技術細節，唔講你日後同人傾會露底：嚴格嚟講，「開源」同「開放權重」係兩件事。開源係連訓練程式碼同資料都公開；開放權重只係公開最後嗰個模型檔案，但訓練過程嘅細節唔公開。業界平時講「開源模型」，其實九成九都係講緊開放權重。

點揀？我畀你一個兩條問題嘅框架。第一，你嘅資料係唔係敏感？ 如果係客戶名單、病歷、未公開嘅財報，咁你唔應該上傳去任何雲端，揀開源。第二，你係唔係要最強性能，而又唔想理硬件？ 咁揀閉源。呢兩條問題答完，你就有答案。

學員可能問「開源模型係唔係一定差？」唔一定。喺好多專門任務上面，一個 7B 嘅開源模型微調過之後，會贏一個通用嘅巨型閉源模型。分別係你要花時間去調。

06

文本、多模態、Embedding、Omni

跟住呢一頁，係一個好多人搞唔清嘅分類。我唔用定義同你講，我用「輸入係乜、輸出係乜」同你分。你只要記住呢個格式，你就唔會亂。

第一種，文本模型。輸入文字，輸出文字。你打一段中文，佢回你一段中文。呢個係最常見嘅，你平時用嘅聊天機械人就係呢類。

第二種，多模態模型。輸入文字加圖片，輸出文字。你影一張相，問佢「呢個係乜」，佢答你。注意佢嘅輸出仍然係文字，佢唔會畫返張圖畀你。

第三種，Embedding 模型。輸入文字，輸出一個向量。呢個係最唔起眼但最重要嘅一種。佢唔會同你傾偈，佢只會將一段文字變成一串數字，即係一個座標。點解要咁做？因為變成座標之後，「意思相近」呢件事就可以用數學計——兩個向量距離越近，意思就越近。你之後學 RAG 嘅時候，就會見到佢嘅威力。

第四種，Omni 模型。任意模態入，任意模態出。可以係文字入、語音出；可以係圖片入、影片出。Jina v5-omni 就係一個例子。呢個係最新嘅方向，亦係最貴嘅方向。

一句話記住：文本模型只識讀寫字，多模態模型識睇圖，Embedding 模型係將語意變成座標，Omni 就係全能。 你日後喺 Hugging Face 揀模型，第一件事就係睇佢係邊一種，唔好揀錯。

補充Embedding 呢個概念，你用一個生活例子講會好明：你喺圖書館搵書，唔係靠書名一模一樣，而係靠「呢本書同我要嘅題目近唔近」。座標就係用嚟量度「近唔近」。 ---

量化與 Hugging Face（15 分鐘 · 07–08）

07

什麼是量化？

呢一頁，係本地部署成敗嘅關鍵。我好多學生就係卡喺呢一步：明明下載咗個模型，點解載入唔到？答案通常係佢下載咗一個「太肥」嘅版本。

先講個背景。原始模型用 FP16 儲存，即係每個參數用十六個位元。你計一計：七十億個參數，每個十六位元，即係每個參數兩個 byte，七十億乘二，大概十四 GB。一部普通手提電腦邊度夠？所以就有咗量化。

量化，就係將啲數字由十六位元壓到八位元、四位元，甚至更低。我用一個你實明白嘅比喻：就好似你張手機相，原本係 RAW 檔，幾十 MB；你轉存成 JPEG，可能得兩三 MB，但睇落去差唔多。 量化做嘅就係呢件事。

COSTAR：六個要素

好，咁點寫？我教你一個框架，叫 COSTAR。六個要素。

附錄三 · 常見誤解逐條拆解

呢一節係我過去幾年教呢堂課，學員最常講嘅十五句「我以為」。你可以喺課堂中間隨時插入，亦可以留到最後做 Q&A 嘅彈藥。

誤解一：「AI 係去資料庫搵答案。」

正確講法：佢係計下一個字嘅機率，唔係查資料庫。

呢個係最根本嘅一個誤解，亦係我課堂第一頁就要處理嘅。你可以用一個實驗證明：你問佢一個歷史上唔存在但係聽落好合理嘅人，佢好可能會編一個出嚟。如果佢係查資料庫，佢會話「搵唔到」。

誤解二：「模型越大就一定越好。」

正確講法：大模型能力強，但係佢需要嘅硬件同成本都高，而且唔一定適合你嘅任務。

誤解五：「本地模型係免費嘅。」

正確講法：本地模型唔需要畀 API 費，但係你要付出硬件成本同電費。

誤解六：「Temperature 調低，佢就會答得準。」

正確講法：Temperature 調低令佢更穩定、更保守，但係唔會令佢由答錯變成答對。

誤解七：「Prompt 越長越好。」

正確講法：Prompt 要清楚，唔係要長。

一句「用三點總結，每點唔超過廿字」比一段三百字嘅背景描述更有用。長 prompt 嘅問題係：重點會被淹沒。

誤解八：「RAG 可以完全解決幻覺。」

因為 RAG 只係確保「佢有資料可以參考」。但係佢仍然可能誤解資料、或者總結錯、或者將兩段資料混埋。RAG 係降低風險，唔係消除風險。

Function Calling 解決「一個模型點樣調用自己嘅 API」；MCP 解決「點樣標準化工具接口」。你可以有 Function Calling 但係冇 MCP；亦可以有 MCP 但係用喺冇 Function Calling 嘅地方。

本地守備範圍：私隱、離線、預算有限。雲端守備範圍：複雜推理、超長文件、最新知識。你要嘅係一套判斷框架，唔係一個「最好嘅工具」。

誤解十三：「Gemini 就係 Google 版 ChatGPT。」

正確講法：佢係一個生態系，唔止係一個聊天機器人。

佢嵌入咗 Gmail、Docs、Sheets、Drive。呢個「融入工作流」係佢同純聊天機械人最根本嘅分別。

附錄六 · 模擬問答演練（Q&A Rehearsal）

呢一節係「模擬對話」，你可以用嚟預演 Q&A。左邊係學員，右邊係你嘅回應。我特意寫成對話形式，因為你要練嘅唔係「知答案」，而係「點樣答」。

場景一 · 學員問：「點解我要用本地模型？雲端唔係更好咩？」

你可以這樣答：

「你問得好好，而且我可以話你聽——如果單睇能力，雲端通常更強。所以如果你問嘅係『邊個更強』，答案係雲端。

但係我想你換一條問題：你要處理嘅資料，係唔係可以離開你部機？

我舉個實際例子。假設你係一間律師樓嘅職員，你要總結一份未公開嘅客戶合約。你用雲端，即係你將客戶嘅機密資料上傳去第三間公司嘅伺服器。呢個動作可能已經違反你嘅專業守則。

喺呢個情況下，雲端幾強都冇用——因為你用唔到。而本地模型雖然差少少，但係佢係『可以用』嘅。

所以本地同雲端唔係『邊個好』嘅問題，係『邊個用得』嘅問題。」

點解要咁答： 唔好直接反駁「雲端更好」。你要承認佢嘅前提（能力上雲端更強），然後將問題轉去另一個維度（私隱）。

場景二 · 學員問：「我部電腦跑唔到 7B，係唔係我唔啱學？」

你可以這樣答：

「唔係。呢個係硬件問題，唔係你嘅問題。

而且我想講一件更重要嘅事：你唔需要跑得起本地模型，都可以理解成堂課嘅內容。

你今日學嘅係兩樣嘢。第一樣係概念——LLM 係機率機器、量化係咩、RAG 點運作。呢啲嘢你唔需要跑模型都可以明。第二樣係判斷——乜嘢情境用乜嘢工具。呢個更加唔需要硬件。

所以如果你部機跑唔到，你唔係學少咗，你係少咗一個體驗。而呢個體驗，你可以喺雲端上面補返。」

點解要咁答： 學員呢條問題背後係一個焦慮——「我係唔係唔夠班」。你要即刻處理呢個焦慮，唔好一開始就講技術。

場景三 · 學員問：「既然 AI 會講錯嘢，我係唔係唔應該信佢？」

你可以這樣答：

「你問嘅方向係啱嘅，但係我想你留意一件事：『唔信』同『查證』係兩件事。

『唔信』係一個終點——你唔信，你就唔會用，問題就完結。但係『查證』係一個過程——你照用，但係你會驗。

我舉個例。你計數用計算機，你會唔會因為「計算機可能撳錯掣」就唔用？唔會。你會用，但係你會檢查個答案合唔合理。

AI 都係一樣。佢係一個工具，佢有佢嘅誤差模式。你嘅工作唔係『信』或者『唔信』，係『知佢幾時會錯』。

而我今日教咗你佢幾時會錯：當佢冇根據嘅時候、當問題超出佢訓練資料嘅時候、當溫度太高的時候。你知呢啲，你就知幾時要查證。」

點解要咁答： 呢條問題係「幻覺」概念嘅自然延伸。你嘅目標係將佢由「二元思維」拉去「判斷思維」。

場景四 · 學員問：「我要學幾耐先算識？」

你可以這樣答：

「我唔會畀你一個時間，因為『識』唔係一個時間點，係一個能力。

不過我可以畀你三條檢查線。第一條：你可以自己裝好 LM Studio、下載一個模型、同佢傾到偈。 呢個大概需要一個週末。第二條：你可以解釋『LLM 係機率機器，唔係知識庫』。 呢個需要你明白，唔係死記。第三條：你可以喺一個具體任務面前，講出你應該用本地定雲端，同埋點解。 呢個係最高嘅標準。

你完成第一條，你就『用得到』。你完成第三條，你就『用得準』。

而我今日想幫你達到嘅係第三條。」

點解要咁答： 學員想要一個明確嘅進度感。你畀佢三條可檢查嘅線，佢就會知道自己在邊。

場景五 · 學員問：「呢啲嘢三年後仲有用咩？」

你可以這樣答：

「如果係具體嘅操作步驟，三年後可能已經唔同。但係有三樣嘢唔會變。

第一，本質。 LLM 係機率機器、量化係取捨、上下文有上限——呢啲係架構層面嘅特性，唔會因為版本更新而消失。

第二，取捨。 私隱同能力嘅取捨、本地同雲端嘅取捨、成本同質素嘅取捨——呢啲取捨唔會消失，只會換個形式。

第三，判斷框架。 我今日教嘅『乜嘢情境用乜嘢』，係一個思考方式，唔係一個產品介紹。

所以我可以話你聽：我今日教你嘅具體操作，可能兩年後要更新。但我今日教你嘅思考方式，可以用十年。」

點解要咁答： 呢條問題係關於「投資回報」。學員想知道自己花時間學嘅嘢值唔值。你要區分「操作」同「觀念」，然後強調後者嘅持久性。

場景六 · 學員問：「點解唔可以全部都交畀 AI？」

你可以這樣答：

「技術上，你可以。但係你會失去一樣嘢：判斷力。

我舉個例。假設你將所有寫作交畀 AI。一年之後，你仲識唔識寫一份清楚嘅報告？你可能識——因為你每次都睇佢寫嘅嘢。但係如果你連睇都唔睇，直接交出去，你就唔會知道邊度有問題。

所以問題唔係『可唔可以』，而係『你會唔會失去某種能力』。

我今日講嘅判斷框架，其實就係一種保留你判斷力嘅方法。你唔係將工作交出去，你係將工作分配出去，但係你保留判斷權。

呢個分別好重要。交出去，你係一個用家。分配出去，你係一個設計者。」

點解要咁答： 呢條問題背後係一個更深嘅焦慮（「我會唔會被取代」）。你嘅答案要同時回應技術問題同情感需求。

附錄十 · 常見課堂狀況處理

呢一節係「突發情況應對」。每一條都係我真實遇過嘅。

點解要老實： 因為如果你亂答，而現場有學員識，你嘅可信度就即刻歸零。反而你老實承認，會令學員覺得你可靠——因為佢哋知你唔會呃佢。

狀況四 · 時間超咗好多

你應該點做： 唔好嘗試追返所有內容。你要做嘅係「保底」——確認學員明白三個核心：LLM 係機率機器、量化係取捨、本地同雲端係分工。

點解： 因為一堂超時嘅課，學員帶走嘅唔係「多啲內容」，而係「疲倦」。你寧願講少啲但講清楚，好過講晒但全部模糊。

狀況五 · 學員程度差異好大

你應該點做： 用「分層任務」。同一個練習，你畀兩個版本——基礎版本（跟步驟做）同進階版本（自己設計）。快嘅學員做進階，慢嘅做基礎。

點解： 因為如果你等最慢嘅，快嘅會悶；如果你追最快嘅，慢嘅會放棄。分層係唯一可以同時照顧兩邊嘅方法。

狀況六 · 冇人答你問題

你應該點做： 改問「舉手投票」或者「一分鐘同伴討論」。因為好多人唔答係因為怕「答錯」，而唔係因為唔識。

點解有效： 舉手同同伴討論嘅心理成本低好多——因為你唔需要公開組織一句完整嘅答案。
